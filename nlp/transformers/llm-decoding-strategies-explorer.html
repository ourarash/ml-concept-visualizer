🎯 Greedy Decoding

At each position, pick the single token with the highest probability. After picking, advance to the next position and re-render its distribution. Deterministic and fast.

🌳 Beam Search

Keep the B highest-scoring partial sequences at each step. Score is the sum of log-probabilities along the path.

Press ▶ Next Step to begin
score(x1..t) = Σ log P(xi | x1..i-1)
💡 Each step expands the B active beams → B×|V| candidates → keep top-B. Short and generic outputs tend to win without length normalization.
⚠ Beam collapse you can see above: the top-B paths all share the same prefix (on the soft …) and only diverge late. Why? At step 1 the top token (on) leads the runner-up (in) by ~1.8 log-units, and every subsequent position uses the same distribution regardless of prefix (the demo is unconditioned). In real LLMs, P(the | "...sat on") ≠ P(the | "...sat in"), which lets beams genuinely diverge — but beam search still collapses in practice. That's why modern LLMs prefer sampling (temperature / top-p) over beam, and when beam is needed, apply length normalization (score / lengthα) or diverse beam search (penalize beams that share prefixes).

⚡ Speculative Decoding

A fast draft model proposes γ tokens up front (committing all γ regardless of whether they'll be accepted); the slow target model then verifies all γ in one batched forward pass. Accept with probability Ptarget/Pdraft; on the first reject, sample a correction and discard the rest. Output distribution equals plain target sampling.

🛑 How decoding stops
Decoding strategies only choose tokens — they never decide on their own when to stop. Stopping is the outer loop's job, and there are exactly two mechanisms in this demo (and in real LLMs):
  • [stopped: EOS] — the sampled token equals the EOS marker. In this demo EOS = . (period). Real LLMs use a special <eos> / <|endoftext|> token in the vocabulary.
  • [stopped: max length] — the decoder has emitted MAX_LENGTH = 7 tokens without hitting EOS, so we cut it off. Real LLMs use the same hard cap (typically 2k–8k tokens) to bound compute.
Beam additionally stops when all top-B beams have hit EOS (or max length). Speculative stops when an accepted draft token (or a correction) is EOS, even mid-batch. Try setting T = 2.0 in Temperature — with a flat distribution at the punctuation slot, you'll often hit max length with ? or , instead of EOS.
📊 Where do the bar heights come from?
Each position's bars are P(v) = softmax(logitv / T) over 10 candidate tokens. Three caveats:
  • Logits are hardcoded, not from a running model. I picked numbers that produce a plausible English sentence and let each strategy demonstrate its mechanism on the same data.
  • Each position shows 10 grammatically curated candidates (preposition at pos 0, determiner at pos 1, adjective at pos 2, …). Real LLMs use a fixed vocabulary of 30k–100k tokens at every position — same softmax, just much wider.
  • Expert vs Amateur (Contrastive section) are two different models scored on the same vocab. Amateur is intentionally peaked on generic tokens (e.g., its slept logit is 3.0 vs expert's 2.0) so contrastive decoding has something to push against.
In a real LLM, these logits come from a forward pass: context → transformer layers → final hidden state → linear projection → vocab logits. Each new token is one forward pass — that's the slow part of inference, and the reason speculative decoding's batched verification gives a speedup.
📚 How this connects to the Part 2 lecture
Reference: ML_LectureSp26_transformers2.pdf
The Part 2 lecture covers how the decoder produces P(next token | context) — BERT vs GPT (slides 1–3), the autoregressive decoder forward pass (slides 4–10), KV caching (slides 11–22), RoPE (slides 23–25), MLA / DeepSeek low-rank KV compression (slides 26–41), and Transformer-XL + relative positional encoding for long context (slides 42–66). This page picks up after all of that: given the model has produced a P(next token) distribution at each step, how do we pick the next token?
Three concrete connections to lecture content:
  1. Each ▶ Generate Next Token click corresponds to one decoder forward pass. Without KV caching it would cost O(N²) attention per step (lecture slide 11); with caching it's O(1×N) per step (slide 14). Greedy/Temperature/Top-k/Top-p all need exactly one cached forward pass per token.
  2. Speculative decoding's speedup directly relies on KV caching. The target model verifies γ drafted tokens in one parallel forward pass — re-using cached K, V from earlier tokens AND scoring all γ positions at once via masked self-attention. Without KV cache, the savings would evaporate. Avg tokens/step > 1 ↔ "got γ+1 token outputs from one forward pass."
  3. Beam search with width B keeps B parallel KV caches — one per active beam. This is why beam width linearly multiplies inference memory cost (and why production LLMs prefer top-p sampling: sampling needs only 1 KV cache regardless of "creativity"). MLA / DeepSeek's low-rank compression (slides 38–40) is partly motivated by exactly this beam-vs-memory tension.
