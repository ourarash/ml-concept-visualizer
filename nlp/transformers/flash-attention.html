FlashAttention — IO-Aware Tiled Attention

Standard attention writes the full N×N attention matrix to HBM and reads it back — bandwidth-bound from the start. FlashAttention keeps work resident in SRAM: stream K, V tiles in, run an online softmax that updates running statistics (m, ℓ, O), and only ever write the final output to HBM. Same answer, but O(N·d) HBM traffic instead of O(N²).

FlashAttention's secret sauce

For each Q tile i, three small vectors live in SRAM and are updated as each K/V tile j streams through. After the last tile, the final Oi is written to HBM.

Sij = Qi · KjT — compute partial scores in SRAM
mnew = max(mi, rowmax(Sij)) — update running max for stability
ℓnew = e^(mi−mnew)·ℓi + sum(e^(Sij−mnew)) — rescale & accumulate denominator
Onew = diag(e^(mi−mnew))·Oi + e^(Sij−mnew)·Vj — rescale O & accumulate weighted values

HBM traffic vs sequence length

Standard scales O(N²); Flash scales O(N·d). The crossover point is around N ≈ d.

▶ Why this is fast

The bottleneck isn't FLOPs — it's HBM. An A100 has 312 TFLOPs of FP16 compute but only 2 TB/s of HBM bandwidth. Standard attention reads/writes the N×N matrix multiple times: at N=4096, d=64, that's ~250 MB of traffic per layer per pass. The compute units sit idle waiting on memory.

SRAM is 10× faster per byte. Each streaming multiprocessor has ~192 KB of L1/SRAM running at ~19 TB/s. If you can keep the working set there, you decouple from HBM bandwidth.

Online softmax is the unlock. Naïve softmax needs the full row to compute the denominator. FlashAttention rewrites it as an incremental update: keep a running max m, running denominator ℓ, and running output O. As each K/V tile streams in, all three are rescaled so the final answer is exactly what naïve softmax would give. No approximation, just smarter math.

The Br trap. FlashAttention's K and V get re-read once for every Q-block — N/Br times total. If you pick Br too small, the re-read overhead exceeds the savings from skipping the N×N matrix and Flash loses to standard. Real implementations set Br ≈ M / (4·d), where M is the SRAM budget — typically 64–128 rows for d=64 on an A100. Try the slider: with the default N=16, d=8, Flash beats Standard at Br=8 but loses badly at Br=2.

The backward pass uses the same trick — it doesn't store the attention matrix; it recomputes it from saved m and ℓ when needed. (See activation checkpointing — same idea, narrower scope.)

Net result with proper Br tuning: 2–4× faster attention end-to-end on long contexts, used by every modern LLM training pipeline.
