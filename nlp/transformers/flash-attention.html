FlashAttention: Tiled, IO-Aware Self-Attention

Standard attention materializes the full N × N score matrix in HBM — GPU off-chip memory. FlashAttention never does. It streams blocks of Q, K, V through on-chip SRAM, fuses the softmax with the matmul, and produces the same output with a fraction of the memory traffic. Toggle the two paths below to see why.

Online Softmax State Per Q-block running statistics

FlashAttention avoids storing S and P by carrying three running statistics per Q row: the running max mᵢ, running normalizer ℓᵢ, and partial output Oᵢ. When a new K/V block arrives, both the output and the normalizer are rescaled by exp(mᵢold − mᵢnew) — the online-softmax trick.

Why FlashAttention wins

1. Attention is memory-bound
On modern GPUs the bottleneck isn't FLOPs — it's HBM bandwidth. Naive attention does O(N²) HBM reads/writes just to stage S = QKᵀ and P = softmax(S).
2. Online softmax
Softmax looks like it needs the whole row before normalizing. With a running max and running sum you can process blocks one at a time and rescale earlier contributions. Output stays numerically identical.
3. Kernel fusion
One CUDA kernel does QKᵀ, softmax, and PV together on SRAM-resident tiles. S and P never exist in HBM — that's where the bandwidth savings come from.
