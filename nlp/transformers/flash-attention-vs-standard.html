Why this matters: attention is memory-bound

The cost of standard attention

Computing $S = QK^\top$ produces an $N \times N$ score matrix. For a sequence length of $N=8192$ in fp16, that's 8192 × 8192 × 2B ≈ 128 MB per head, written to HBM, read back for softmax, written again, then read once more for $PV$.

The GPU memory wall

An A100 has ~40 MB of on-chip SRAM but ~1.5 TB/s of HBM bandwidth vs ~19 TB/s of SRAM bandwidth. Attention spends most of its time waiting on HBM, not on math.

FlashAttention's idea

Tile $Q$, $K$, $V$ into blocks small enough to fit in SRAM. Compute attention block-by-block and combine the partial softmaxes with an online rescaling trick. The full $S$ and $P$ matrices never exist in HBM.

The math, side by side

Standard attention
$$ S = \frac{QK^\top}{\sqrt{d}} \in \mathbb{R}^{N\times N} $$
$$ P = \mathrm{softmax}(S) $$
$$ O = PV $$

Each line is a separate kernel; each materialises its full output to HBM before the next can start. Memory traffic is $\mathcal{O}(N^2 + Nd)$.

FlashAttention (online softmax)
For each block $S_{ij} = Q_i K_j^\top / \sqrt{d}$ kept in SRAM:
$$ \tilde m_{ij} = \mathrm{rowmax}(S_{ij}),\quad \tilde P_{ij} = \exp(S_{ij} - \tilde m_{ij}) $$
$$ m_i^{\text{new}} = \max(m_i,\, \tilde m_{ij}) $$
$$ \ell_i^{\text{new}} = e^{m_i - m_i^{\text{new}}} \ell_i + e^{\tilde m_{ij} - m_i^{\text{new}}} \mathrm{rowsum}(\tilde P_{ij}) $$
$$ O_i \leftarrow \mathrm{diag}(e^{m_i - m_i^{\text{new}}}) O_i + e^{\tilde m_{ij} - m_i^{\text{new}}} \tilde P_{ij} V_j $$

Only $O$, the running max $m$, and the running normaliser $\ell$ live in HBM — all $\mathcal{O}(N)$. Total HBM traffic drops to $\mathcal{O}(N^2 d^2 / M)$ where $M$ is the SRAM size.

Key takeaways

  1. Attention is memory-bound, not compute-bound. The win comes from fewer HBM round-trips, not faster matmuls — the GPU's compute units were already idle waiting on memory.
  2. The N×N matrix never needs to leave SRAM. Standard attention writes $S$ and $P$ to HBM purely as a programming convenience; FlashAttention proves you don't have to.
  3. Online softmax is the enabling math. By tracking the running max $m$ and normaliser $\ell$ per row, partial softmaxes from different K/V tiles can be combined exactly — the result is bit-equivalent to the standard formulation, not an approximation.
  4. Memory savings → longer contexts. Going from $\mathcal{O}(N^2)$ to $\mathcal{O}(N)$ HBM for intermediates is what unlocks 32k, 128k, 1M-token context windows on the same hardware.
  5. It's not free. FlashAttention does more FLOPs (recomputes $S_{ij}$ for the backward pass instead of caching $P$), but those extra FLOPs cost ~0 in wall-clock because the kernel was waiting on memory anyway. Roofline-wise, you're moving left toward the compute-bound regime.

Section II — Online Softmax: Tiling and Rescaling

Section I treated online softmax as a black box inside the FlashAttention inner loop. This section opens that box on a plain 1-D vector. The recurrence — running max $m$, running normaliser $\ell$, and the rescale $e^{m_{\text{old}} - m_{\text{new}}}$ — is the entire algorithmic core of FlashAttention.

Why softmax can't be tiled naively

Softmax of a row $x \in \mathbb{R}^N$ is $\mathrm{softmax}(x)_i = e^{x_i} / \sum_j e^{x_j}$. The denominator depends on all $x_j$. If you split $x$ into blocks and softmax each independently, every block will sum to 1 — but the relative magnitudes between blocks will be wrong.

Each block sums to 1 internally, total ≈ 2. Probabilities don't reflect the global distribution.

The fix: carry forward two scalars per row — running max $m$ and running normaliser $\ell$ — and apply an algebraic rescale whenever a new block updates the max.

The online recurrence

For each block $b$ of the row
$$ \tilde m_b = \max_{x \in b}\, x $$
$$ m^{\text{new}} = \max(m^{\text{old}},\, \tilde m_b) $$
$$ \ell^{\text{new}} = e^{m^{\text{old}} - m^{\text{new}}}\,\ell^{\text{old}} \;+\; e^{\tilde m_b - m^{\text{new}}}\!\!\sum_{x \in b}\!\! e^{x - \tilde m_b} $$
$$ m^{\text{old}} \leftarrow m^{\text{new}},\quad \ell^{\text{old}} \leftarrow \ell^{\text{new}} $$
After all blocks
$$ p_i = \frac{e^{x_i - m^{\text{final}}}}{\ell^{\text{final}}} $$

The factor $e^{m^{\text{old}} - m^{\text{new}}}$ retroactively corrects the old running sum: the previous terms were scaled relative to the old max, but the new max is bigger, so each old term needs an extra $e^{-(m^{\text{new}} - m^{\text{old}})}$ factor. That single rescale is the heart of FlashAttention.

Pseudocode

def online_softmax(x, B):
    m = -inf            # running max
    ℓ = 0               # running normaliser
    for b in blocks(x, B):
        m̃     = max(b)                              # block-local max
        m_new = max(m, m̃)                       # update running max
        ℓ     = exp(m - m_new) * ℓ \
              + exp(m̃ - m_new) * sum(exp(b - m̃))   # rescale + add
        m     = m_new
    return exp(x - m) / ℓ     # final divide

Section III — Backward Pass: Recomputation

The forward pass writes only $O$, $m$, and $\ell$ to HBM — never the $N\!\times\!N$ matrices. But the backward pass needs $P$ to compute gradients of softmax. FlashAttention's solution: recompute $S_{ij}$ and $P_{ij}$ block-by-block from the saved $m$ and $\ell$. The recompute is "free" because the kernel was waiting on memory anyway.

Why backward needs the attention probabilities

Forward (recap)
$$ S = QK^\top / \sqrt{d} $$
$$ P = \mathrm{softmax}(S),\qquad O = PV $$

Standard implementations save $P$ to HBM for the backward pass — that's $\mathcal{O}(N^2)$, again.

Backward gradients
$$ dV = P^\top\, dO,\qquad dP = dO\, V^\top $$
$$ dS = P \odot \big(dP - \mathrm{rowsum}(dP \odot P)\big) $$
$$ dQ = dS\, K / \sqrt{d},\quad dK = dS^\top Q / \sqrt{d} $$

$dV$, $dP$, and $dS$ all reference $P$. So backward needs either $P$ from HBM, or the means to regenerate $P$.

The recomputation trick

What's saved from forward

$O$ ($N\!\times\!d$), $m$ ($N$), $\ell$ ($N$). Total $\mathcal{O}(Nd)$. No N×N matrix.

What's recomputed in SRAM

For each $(i,j)$ block: $S_{ij} = Q_i K_j^\top/\sqrt{d}$, then $P_{ij} = e^{S_{ij} - m_i} / \ell_i$ using saved $m$ and $\ell$. $P_{ij}$ exists only in SRAM, only briefly.

What it costs

Extra $Q_i K_j^\top$ matmul per block. But the kernel was memory-bound, so the GPU's ALUs were idle — wall-clock cost ≈ 0.

Flash does more compute and less memory traffic. On a memory-bound kernel that's a strict win — the extra FLOPs cost ~0 wall-clock because the GPU was waiting on HBM anyway.

Roofline intuition

An A100 has ~312 TFLOPs of fp16 compute and ~1.5 TB/s HBM. The arithmetic intensity needed to saturate compute is ~200 FLOPs per byte. Standard attention sits at ~$\mathcal{O}(1)$ FLOP per byte — squarely memory-bound.

Recomputing $S_{ij}$ multiplies FLOPs by a small constant but increases arithmetic intensity, since the same HBM I/O now produces more useful work. The kernel moves rightward toward the compute roof. Wall-clock-wise the recompute is masked by cycles already spent waiting on memory.

Each algorithm's position on a roofline. Recompute moves rightward.

Backward pseudocode

# Saved from forward: O, m, ℓ. Inputs: dO, Q, K, V. Outputs: dQ, dK, dV.
for j in range(num_kv_blocks):
    Load K_j, V_j into SRAM;  dK_j = 0;  dV_j = 0
    for i in range(num_q_blocks):
        Load Q_i, O_i, dO_i, m_i, ℓ_i
        S_ij = Q_i · K_jᵀ / sqrt(d)            # RECOMPUTE
        P_ij = exp(S_ij - m_i) / ℓ_i      # RECOMPUTE
        dV_j += P_ijᵀ · dO_i
        dP_ij = dO_i · V_jᵀ
        D_i   = rowsum(dO_i ⊙ O_i)               # softmax-Jacobian helper
        dS_ij = P_ij ⊙ (dP_ij - D_i)
        dQ_i += dS_ij · K_j / sqrt(d)            # scatter-add
        dK_j += dS_ijᵀ · Q_i / sqrt(d)
    Write dK_j, dV_j back to HBM

Identity used: $\mathrm{rowsum}(dP \odot P) = \mathrm{rowsum}(dO \odot O)$, so $D_i$ can be computed from saved $O$ and incoming $dO$ without ever assembling $dP$ for the whole row.

Reference: Dao, Fu, Ermon, Rudra, Ré — FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness (NeurIPS 2022). Backward is Algorithm 4.
