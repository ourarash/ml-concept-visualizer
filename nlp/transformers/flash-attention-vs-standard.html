FlashAttention vs Standard Attention

An interactive walkthrough of why standard attention is bottlenecked by GPU memory and how FlashAttention rewrites the algorithm — with tiling and an online softmax — so the full $N \times N$ attention matrix is never written to HBM. Press Step to advance both algorithms in lock-step and watch the HBM I/O counters diverge.

Why this matters: attention is memory-bound

The cost of standard attention

Computing $S = QK^\top$ produces an $N \times N$ score matrix. For a sequence length of $N=8192$ in fp16, that's 8192 × 8192 × 2B ≈ 128 MB per head, written to HBM, read back for softmax, written again, then read once more for $PV$.

The GPU memory wall

An A100 has ~40 MB of on-chip SRAM but ~1.5 TB/s of HBM bandwidth vs ~19 TB/s of SRAM bandwidth. Attention spends most of its time waiting on HBM, not on math.

FlashAttention's idea

Tile $Q$, $K$, $V$ into blocks small enough to fit in SRAM. Compute attention block-by-block and combine the partial softmaxes with an online rescaling trick. The full $S$ and $P$ matrices never exist in HBM.

The math, side by side

Standard attention
$$ S = \frac{QK^\top}{\sqrt{d}} \in \mathbb{R}^{N\times N} $$
$$ P = \mathrm{softmax}(S) $$
$$ O = PV $$

Each line is a separate kernel; each materialises its full output to HBM before the next can start. Memory traffic is $\mathcal{O}(N^2 + Nd)$.

FlashAttention (online softmax)
For each block $S_{ij} = Q_i K_j^\top / \sqrt{d}$ kept in SRAM:
$$ \tilde m_{ij} = \mathrm{rowmax}(S_{ij}),\quad \tilde P_{ij} = \exp(S_{ij} - \tilde m_{ij}) $$
$$ m_i^{\text{new}} = \max(m_i,\, \tilde m_{ij}) $$
$$ \ell_i^{\text{new}} = e^{m_i - m_i^{\text{new}}} \ell_i + e^{\tilde m_{ij} - m_i^{\text{new}}} \mathrm{rowsum}(\tilde P_{ij}) $$
$$ O_i \leftarrow \mathrm{diag}(e^{m_i - m_i^{\text{new}}}) O_i + e^{\tilde m_{ij} - m_i^{\text{new}}} \tilde P_{ij} V_j $$

Only $O$, the running max $m$, and the running normaliser $\ell$ live in HBM — all $\mathcal{O}(N)$. Total HBM traffic drops to $\mathcal{O}(N^2 d^2 / M)$ where $M$ is the SRAM size.

Key takeaways

  1. Attention is memory-bound, not compute-bound. The win comes from fewer HBM round-trips, not faster matmuls — the GPU's compute units were already idle waiting on memory.
  2. The N×N matrix never needs to leave SRAM. Standard attention writes $S$ and $P$ to HBM purely as a programming convenience; FlashAttention proves you don't have to.
  3. Online softmax is the enabling math. By tracking the running max $m$ and normaliser $\ell$ per row, partial softmaxes from different K/V tiles can be combined exactly — the result is bit-equivalent to the standard formulation, not an approximation.
  4. Memory savings → longer contexts. Going from $\mathcal{O}(N^2)$ to $\mathcal{O}(N)$ HBM for intermediates is what unlocks 32k, 128k, 1M-token context windows on the same hardware.
  5. It's not free. FlashAttention does more FLOPs (recomputes $S_{ij}$ for the backward pass instead of caching $P$), but those extra FLOPs cost ~0 in wall-clock because the kernel was waiting on memory anyway. Roofline-wise, you're moving left toward the compute-bound regime.
Reference: Dao, Fu, Ermon, Rudra, Ré — FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness (NeurIPS 2022).
