DeepSeek V4 Hybrid Sparse Attention

V3.2 ran a single flavour of sparse attention (DSA) across every layer. V4 stacks three different attention types in different layers — each tuned to a distance regime in long-context inference. Recent tokens get DSA's lightning indexer; mid-distance tokens get CSA's token-wise KV compression; very distant tokens collapse into HCA's heavily compressed summaries. The result: million-token context without million-token memory or compute.

DSA — DeepSeek Sparse Attention
Carried over from V3.2. Lightning indexer scores past tokens; only the top-k get full attention. Best for recent context where exact recall matters.
CSA — Compressed Sparse Attention
Token-wise compression of K, V vectors. Each token still has its own K, V — just smaller. Best for moderately distant context where rough fidelity is enough.
HCA — Heavily Compressed Attention
Aggressive compression: groups of tokens collapse into a single summary representation. Best for very distant context where only the gist needs to survive.

Why hybrid? The million-token wall

Vanilla full attention

For $N{=}10^6$ tokens, KV cache scales linearly: $O(N d)$ per layer. Compute scales as $O(N)$ per query token. Both crush GPU memory and bandwidth at multi-million-token contexts.

V3.2's DSA-only approach

Lightning-indexer selection is great for recent context but still keeps the full KV cache for indexing — the cache itself doesn't shrink. For 1M-token contexts the cache is still the bottleneck.

V4's hybrid fix

Match the storage to the distance: keep close tokens at full fidelity (DSA), squeeze mid tokens (CSA), summarise far tokens (HCA). The cache footprint becomes sub-linear in context length.

Architecture: three attention types stacked across layers

Different layers use different attention types. Earlier (and typically more frequent) layers focus on near context with DSA; interleaved CSA layers handle medium-distance retrieval; sparse HCA layers anchor the long-range context. The exact interleaving below is illustrative — real configurations are tuned per benchmark.

Why interleave? Each attention type has a different inductive bias. Stacking them lets the model query close, mid, and far context cooperatively rather than forcing one mechanism to do all three jobs.

Why DSA gets more layers: recent context is what most queries need. Allocating more layers to DSA matches the workload distribution.

Why HCA is the rarest: per-layer it stores the least, so a few HCA layers are enough to keep the long tail of context accessible.

Key takeaways

  1. Match storage to distance. Recent tokens deserve full-fidelity K, V; ancient tokens only need a coarse summary. One-size-fits-all attention pays for fidelity it doesn't use.
  2. DSA narrows compute, CSA narrows storage, HCA narrows both. DSA reduces FLOPs but keeps the cache; CSA shrinks cache and the dot-product cost per token; HCA collapses entire token groups so even the cache count drops.
  3. Layer-level specialisation, not token-level. A given layer commits to one attention type — the diversity comes from stacking different layers, not switching mechanisms within a layer. This keeps the kernel implementation clean.
  4. Hybrid effective context $\gg$ DSA-only. At a fixed memory budget, V4 fits roughly an order of magnitude more tokens than V3.2 because the cache footprint grows sub-linearly in $N$.
  5. Quality is preserved differently per regime. DSA preserves exact-recall on near tokens; CSA preserves the dominant directions of K, V; HCA preserves coarse semantic anchors. Together they cover the full distance spectrum without any single mechanism being asked to do an unnatural job.
